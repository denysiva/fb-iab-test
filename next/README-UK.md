# NEXT v3 — перевірка повноекранного режиму кнопкою

Посилання без параметрів: https://denysiva.github.io/fb-iab-test/next/

Діагностика: https://denysiva.github.io/fb-iab-test/next/?iab_debug=1

У мобільному Meta ця версія за замовчуванням використовує режим `button`. Автоматичного скролу на старті немає. Натискання NEXT, YES, NO або варіанта відповіді запускає спробу розгортання. У звичайному браузері без параметрів експеримент вимкнений; примусовий тест поза Meta — `?iab=button`.

## Що змінено проти /auto/

- Додано `webkitRequestFullscreen` і старіше написання `webkitRequestFullScreen`. Відсутність стандартного `document.fullscreenEnabled` більше не відсікає WebKit API.
- Запит виконується синхронно на фазі capture справжнього click — до того, як квіз приховає поточний крок. Штучних кліків або затримки перед запитом немає.
- При відмові наступне справжнє натискання може повторити запит. Якщо доступні обидва API, після невдачі на наступному натисканні перевіряється інший.
- Обробник охоплює NEXT, YES, NO та варіанти відповідей на всіх проміжних кроках. Обидві відповіді на кроках 2–3 ведуть далі, як в оригіналі.
- Підтримано стандартні та WebKit-події входу, відмови й виходу, а також відповідні способи виходу.
- Вхід зараховується тільки після підтвердження фактичного fullscreen-елемента. Promise без входу або мовчазний виклик старого API не вважаються успіхом.
- При відмові сторінка залишається доступною для робочої механіки зі свайпом. Саме блокування HTML під видимою панеллю не видається за успішне приховування панелі Meta.

Код квізу, CSS, фотографії та переклади побайтово збігаються з попередньою версією. В HTML прибрано лише кінцеві пробіли; тексти й адреси переходів збережено. Зміни поведінки обмежені вибором початкового режиму та контролером розгортання. Фінальний CTA веде до офера за старою логікою й не затримується заради fullscreen.

## Як перевірити на телефоні

1. Відкрити /next/ у Facebook, не прокручуючи сторінку.
2. Натиснути NEXT. Перевірити саме нативні кнопки Facebook, а не лише вигляд сторінки.
3. Якщо панель залишилася, пройти YES/NO і натиснути відповідь на одному з наступних кроків. Кожне нове натискання може повторити запит; невдала перша спроба більше не вимикає всі наступні.
4. Для пояснення відмови відкрити посилання діагностики та повторити натискання.
5. Кнопка ⌄ повертає звичайну прокрутку й вимикає експеримент до перезавантаження. Свайп лишається запасним варіантом. /auto/ залишається попередньою робочою версією.

## Значення діагностики

- `API:standard+webkit` або `API:webkit` — які методи браузер відкрив сторінці.
- `API:none/unavailable` — методів fullscreen для HTML-елемента немає; цей спосіб кнопкою недоступний.
- `requesting-standard` / `requesting-webkit` — запит відправлено, підтвердження ще немає.
- `entered` разом із `fullscreen-api` — браузер підтвердив повноекранний HTML-елемент.
- `rejected-NotAllowedError` — браузер відхилив запит. Сам код помилки не доводить точну причину відмови.
- `fullscreen-error-event` — браузер повідомив про невдалий вхід через подію.
- `no-entry` — підтвердження входу не надійшло за 1,2 секунди.
- `tries` — кількість спроб після натискань; `step` — крок, на якому була остання спроба, до перемикання квізу.
- `locked · native-scroll` — спрацював резервний шлях зі свайпом.
- `viewport-heuristic` — непрямий сигнал збільшення висоти; він не доводить приховування панелі Facebook.

## Що перевірено

- 24 автоматизовані перевірки логіки, включно з WebKit без стандартного API, повторною спробою після відмови, переходом між двома API, асинхронною відмовою, виходом та збереженням механіки A.
- У настільному вбудованому браузері стандартний метод Fullscreen API та окремо його метод з префіксом `webkit` увійшли у fullscreen натисканням NEXT; квіз перейшов з кроку 1 на 2, запит зареєстровано ще на кроці 1.
- У браузері пройдено всі чотири маршрути YES/YES, YES/NO, NO/YES, NO/NO із примусовою відмовою API в локальній тестовій сторінці: усі дійшли до кроку 7, кожне натискання NEXT або відповіді повторювало спробу, помилкове блокування не виникало.
- У тестових проходах немає помилок JavaScript. Вихід із розгортання перевірено.
- Реальна підтримка саме Facebook на iPhone ще не підтверджена для v3. Результат настільного браузера не замінює цей тест.

## Межа можливостей сторінки

Apple документує підтримку JavaScript fullscreen у WKWebView, але її має ввімкнути власник додатка через `isElementFullscreenEnabled`. Це налаштування Facebook, а не параметр лендінгу. Додавання WebKit-виклику виправляє пропуск у попередній реалізації, але не гарантує, що Meta дозволяє його на конкретному iPhone.

Джерело: [Apple, What's new in WKWebView](https://developer.apple.com/videos/play/wwdc2022/10049/).

GitHub Pages — тестове розміщення. Переходи до офера та зовнішні скрипти трекера збережені; статичний хостинг не замінює маршрутизацію трекера.

Уточнення від 24.10.2026: метод з префіксом `webkit` не доводить використання рушія WebKit. User-agent тестового настільного браузера — Chrome 155; перевірки не відтворюють оболонку Facebook на iPhone.
