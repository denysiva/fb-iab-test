# NEXT v6 — ізольований запит справжнього fullscreen

Це експеримент, а не підтверджене виправлення для Facebook на iPhone. Станом на 24.10.2026 користувач підтвердив: `/press/` не ховає панель навіть при утриманні NEXT; справжній свайп працює. Результату v6 на цільовому телефоні ще немає.

## Посилання

- Лендінг: https://denysiva.github.io/fb-iab-test/tap/
- Лендінг з поясненням результату: https://denysiva.github.io/fb-iab-test/tap/?iab=tap&iab_debug=1
- Окрема перевірка без квіза й сторонніх скриптів: https://denysiva.github.io/fb-iab-test/tap/probe.html?iab_debug=1

У мобільному Meta режим `tap` обирається автоматично. У звичайному браузері він вимкнений; параметр `iab=tap` вмикає його для перевірки. `iab=off` вимикає.

## Що змінено від v3

Попередній `/next/` одночасно викликав fullscreen на `<html>`, зсував документ і відразу перемикав крок. v6 запитує fullscreen для постійного контейнера квіза `<main>` в оригінальному `click`, не зсуває документ для запуску та чекає завершення запиту перед перемиканням кроку. Це усуває можливі перешкоди тесту; доказу, що саме вони спричиняли відмову Facebook, немає. Сам Fullscreen API вже пробували у v3 — це його ізольована перевірка, не новий обхід обмежень.

Немає штучної висоти сторінки, блокування прокрутки, обробників натискання/свайпу чи імітації жесту. Успіх визначається лише реальним `fullscreenElement`, а не зміною висоти екрана. Коли браузер не надає API, NEXT працює відразу. Після відмови NEXT продовжує квіз; без відповіді очікування обмежене 1,5 с (незалежний захист квіза — 1,8 с). Для наступного справжнього натискання можна спробувати другий доступний метод. Після виходу користувача автоматичні повтори припиняються.

На короткому екрані звичайна прокрутка до кнопки може знадобитися для верстки. Повернення на початок нового кроку виконується лише після завершення запиту. Воно не використовується як спосіб приховати панель.

Вихід із fullscreen доступний круглою кнопкою вгорі праворуч і штатними засобами браузера. Оригінальні тексти, 12 фото, переклади, фінальне посилання та два зовнішні підключення лендінгу збережено. Власні сторонні інтеграції оригіналу залишаються; `probe.html` їх не підключає.

## Як читати результат

Відкрити діагностичне посилання саме в Facebook, без свайпу звичайно натиснути NEXT. Перевірити також YES/NO на наступних кроках.

- «Справжній fullscreen увімкнено» — браузер підтвердив розгортання HTML-контейнера. Окремо оцінити, чи зникла панель Facebook.
- «Браузер не надав API» — у цьому середовищі немає доступного методу для запиту.
- `rejected-…` / «Браузер відхилив запит» — запит відхилено; подробиці в локальному звіті.
- «Браузер не підтвердив вхід» — метод був, але вхід не підтверджений за 1,5 с.

Якщо лендінг відмовляє, `probe.html` перевіряє той самий API без інших інтеграцій. Якщо й він не надає API або відмовляє, це сильніше вказує на обмеження середовища; JavaScript не може змінити native preference Facebook.

Діагностика доступна лише з `iab_debug=1`; журнал локальний, без автоматичного надсилання, збереження відповідей, cookies чи рядка параметрів URL. Ручна оцінка видимості панелі відділена від результату API.

## Перевірено

16 автоматизованих перевірок логіки: підтримка API, синхронний виклик, справжнє підтвердження входу, відмова, тайм-аут, повтори, вихід, відсутність програмної прокрутки в контролері.

У настільному Chrome 155: справжній fullscreen на NEXT, усі 6 переходів до фіналу зі збереженням fullscreen, вихід; усі 4 маршрути квіза за відсутності API; змодельована відмова і тайм-аут; подвійний тап не пропускає крок. Розміри 390×844, 320×568, 844×390; горизонтального переповнення немає, основні кнопки від 48 px. Емуляція розміру не є тестом реального iPhone.

## Межа можливостей

Apple вимагає, щоб застосунок увімкнув `WKPreferences.isElementFullscreenEnabled` для element fullscreen у WKWebView. Цей параметр належить власнику застосунку; лендінг не може його увімкнути. За відсутності дозволу цей експеримент не обіцяє прибрати панель кнопкою.

Джерела: [Apple WWDC22](https://developer.apple.com/videos/play/wwdc2022/10049/), [WKPreferences](https://developer.apple.com/documentation/webkit/wkpreferences/iselementfullscreenenabled), [Fullscreen Standard](https://fullscreen.spec.whatwg.org/).
